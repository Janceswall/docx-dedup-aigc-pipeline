# 第二轮：拿到检测报告后的精修

第一轮是**预降重**（无报告、全文盲改高风险段）。拿到标红报告后要做的是**精修**——
只动被标记的句子，把预降重留下的长重合彻底清掉。这一轮的效率和质量都远高于第一轮。

## 1. 先解析报告，不要肉眼读

用 `scripts/dedup.py report`（兼容壳：`scripts/parse_paperpass_report.py`）：

```bash
python3 scripts/dedup.py report "<解压后的报告目录>" --paras
```

它从报告包里取三样东西：

| 来源 | 取什么 | 用途 |
|---|---|---|
| `htmls/js/detaildata.js` | `score`（总相似度）、`pScore/tScore/uScore`（各来源占比）、`similarResources`（top 相似来源及各自百分比） | 判断"差多少"，以及重复的对手是谁 |
| `htmls/js/texthtmldata.js` 的 `detailJsonData` | 逐句相似度（0~100） | 拿到**完整的命中句子清单**，比着色版更全（着色版会漏掉跨 run 的边界） |
| `报告_Word标红版/*查重报告*.docx` | 逐段字体颜色 | 拿到**段落级定位**，直接对应文档段号 |

**着色约定**（PaperPass 用字体颜色，不是高亮 `w:highlight`）：

| 颜色值 | 含义 | 处理 |
|---|---|---|
| `F39800` | 橙 · 相似 | 改 |
| `F12828` | 红 · 重复 | 必改，相似度最高 |
| `000000` | 正常 | 不动 |

> 坑：`w:highlight` 全是 `none`，解析颜色必须读 `w:color` 的 `val`。
> 坑：报告包里同时有"查重标红版"和"AIGC标红版"，AIGC 版通常是全黑（免费版不给逐句着色），
> 文件名匹配要先精确到"标红版_查重报告"，否则会匹配错文件。

**PaperPass 免费版不给逐句 AIGC**：`reduceaigcpagedata.js` 里 score 全为 0。
判断 AIGC 结果要用 `detaildata.js` 的 `aiScore` 和 `texthtmldata_ai.js` 的逐句评分。

## 2. 建立"报告段号 ↔ 文档段号"映射

报告里的段号是**去掉空段后重新计数**的，和文档实际段号常常不等
（报告往往会跳过空段，两者相差的正是空段的数量）。

**零依赖通道不需要字符坐标**，拿到真实段号即可完成映射：

```bash
python3 scripts/dedup.py prepare 送检稿.docx -o work/    # sheet.json 含段号/角色/全文
python3 scripts/dedup.py report "<报告目录>" --paras      # 报告侧逐段着色
```

把两份输出并列一看，逐段比对首句，确认 `pN（报告）` 与 `pN（文档）` 一一对应后再往下走。
（只有走编辑器通道时才需要 `doc_resolve_document_structure` 拿 `start_index/end_index`。）

## 3. 改写策略：按标记类型区别对待

**红色（重复）**：不能换同义词。要拆句重组——换主语、换语序、换叙述视角、把长句拆成两句、
把"总—分"改成"分—总"。这类句子的相似度评分通常很高，只换词会原地不动。

**橙色（相似）**：可做句法级重构 + 换意象/换搭配。重点看是不是通用句式
（"所谓X，既包括A，也涵盖B""在…的思想里，…是…的一个组成部分"）——这类模板句是命中大户。

**降重的同时顺手修语病**：报告只告诉你哪里重复，但既然要逐句重写，就顺便把语法问题一起解决。
常见的、报告不会标但必须改的：

| 类型 | 例 |
|---|---|
| 冒号前后逻辑断裂 | "好比种下一粒种子：他们听得懂外界的讯息" → 种子不会"听懂" |
| 缺主语 / 句子成分不全 | "会上在议题刚提出的那几天，内容挑听众能懂的" |
| 主谓搭配不当 | "业务…向外发散"、"决心…得到锻炼"、"指标…周而复始" |
| 排比分句主语来回跳 | "手套要戴好，涂料调匀，刷子蘸上溶剂" → 统一主语 |
| 自相矛盾 | "这一环最重要，但另一环的影响更关键" |
| 官名/文献名写法错误 | 引用的法规、标准、文献名称与官方正式名称不一致 |
| 赘余 | "相互交换意见"（交换已含相互义）、"落笔的过程中" |

## 4. 不可绕过的三类保留项

这几类在报告里也会被着色，**必须保留，不要为了降数字去动**：

1. **文档标题** —— 改标题是改题目，性质完全不同。以某个通用主题为题的文档，
   标题与同类文献相似是必然的。
2. **官方文献全称** —— 引用的法规、标准、机构名等专用名称，写法必须与官方一致。
   若原稿名称本身就写错了，**订正**（这是准确性提升），订正后通常能顺带消掉原句的重复。
3. **引文原文** —— 名言、诗句、篇名、法条。带引号即合规引用。

交付时必须把这三类**单独列出来说明**，否则用户会以为"没改干净"。

## 5. 验收口径

改完不要只比对"和上一版的重合"，那是错的口径（上一版刻意保留的未标红文字本来就该重合）。
正确的口径是：**报告标记过的句子，是否已经被打断**。

一条命令即可：

```bash
python3 scripts/dedup.py residue "PaperPass-检测报告/" 改写稿v2.docx
```

它对报告里每一处红色（重复）/橙色（相似）标记，计算该标记文本在新稿全文中的
**最长残留连续长度**，要求 < 13 字。输出形如：

```
 = 残留(合规保留) 标记 18字 最长残留 18  [橙·相似] 某主题的实践观察与思考
!! 残留待处理   标记 30字 最长残留 16  [红·重复] ……（需回炉重改）
OK 已打断       标记 42字 最长残留  0  [红·重复] 举例而言，被标记的整句在新稿中已被拆开，……
---
标记片段 18 处：残留 3 处，其中需继续处理 1 处
```

残留分三类：**已打断**（残留 0）、**合规保留**（残留在标题/引文/专名里，不计入待处理）、
**需继续处理**（其余长残留，必须回炉）。只有第三类为 0，才算这一轮过了。

格式侧另跑一次：

```bash
python3 scripts/dedup.py verify 送检稿.docx 改写稿v2.docx --changed 2,4,5,...
```

这两项加上对照表生成，可以用 `dedup.py run` 一条命令串起来：

```bash
python3 scripts/dedup.py run work/sheet_r2.json -o out2/ --report "PaperPass-检测报告/"
```

## 6. 交付时要说清的三件事

1. **报告怎么读**：总相似度、各来源占比、AIGC 是多少、命中多少句多少字、占比多少
2. **标记清除率**：改前命中 X 字（占正文 Y%），改后残留 Z 字（仅剩专名与引文），
   据此推算预期数值——但**明确说"以再次检测为准"**，不要承诺具体分数
3. **参考文献命中的特殊情形**：占比最高的相似来源常是本文自己引用的文献
   （"已标注引用但系统仍计分"），这不是问题，可以主动说明

## 7. 用脚本驱动，不要手写单元格

对照表和修改说明的文本一律**从改前/改后两份 docx 里程序化抽取**，
不要凭记忆重打——长文档里任何一个手抄的句子都可能出错，而用户是要逐字核对的。
生成完在文档末尾注明"由程序直接抽取，未做人工转录"，用户才敢信。
